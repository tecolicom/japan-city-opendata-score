# 監視層 (L3) — 入口

**この文書は枠だけ。本スライス (第一スライス) では実装しない。** 何も動いておらず、動くと約束するものでもない。範囲の宣言と、実装しないことで生じる制約を書く。

## 位置づけ

| 層 | 内容 | 状態 |
|---|---|---|
| L1 | 知識ベース — 語彙・schema・family・指標の定義 | 実装済み |

## L3 が担う範囲 (宣言)

| 範囲 | 何をするか | 今ある代用 |
|---|---|---|
| 時系列観測 | 同じ配信元を時間をおいて観測し、履歴を残す (観測窓・履歴・差分検知) | なし。観測は単発の 1 回 |
| 消滅検知 | 配信元・フィード・恒久 URL が消えた / 移転したことを検知する | `assessments` の `status: gone` / `moved` を**手で**書く欄だけ |
| 横断比較 | 自治体・県・family をまたいで、時間軸を含めて比べる | `npm run score` の静的な集計だけ |

## 実装しないことで生じる制約 (利用者が知っておくこと)

- **G (継続性) は `g_proxy` (代理指標版) として存在する。** 本来の G は「観測期間中の可用性」で、1 回の訪問では測れない。`g_proxy` は単発訪問で取れる代理 (フィード URL の応答、`stable_url`、版表記) だけで、**時間を通じた継続性を測ったものではない**。時系列版の G と取り違えないよう、軸の別名を `g_proxy` にしている (`docs/index.md` §7.3)
- **「恒久 URL か」(`stable_url`) は書けない。** URL の形から恒久性は判断できず、時間をおいた再観測が要る。現状は 0 件
- **フィードの障害の継続期間は分からない。** 観測は 1 回。`families/*.yaml` の `known_incidents` に開始が記録されているだけ
- **F の `measured` は 0 件。** 配信元そのものでの条件付き GET は単発でも取れるので L3 の仕事ではなく、**本スライス内で誰でも足せる** (`docs/playbook.md`)

## 設計の指針 (実装するときの前提。確定ではない)

- **礼儀を緩めない。** 定期観測は単発より負荷が累積する。`politeFetch` の規則 (robots・間隔・キャッシュ・連絡先付き User-Agent) に加え、頻度の上限を設計に入れる
- **履歴は事実として残す。** 「消えた」は観測の欠落であって、取得失敗 1 回で `gone` にしない
- **由来の規則を維持する。** 時系列の観測は `measured`。観測窓が足りない間は `unknown` (0 点ではない)
- **実行基盤は未定。** 国外 IP (CI) からの遮断はスコアに入れず構造化フィールドで持つ (`docs/index.md` §5)
